# Налаштування Supabase для Physics Teacher Hub

Supabase — це хмарна база даних (PostgreSQL) зі вбудованим входом користувачів. Безкоштовного тарифу достатньо для особистого кабінету вчителя.

> Інтерфейс Supabase час від часу оновлюється, тож назви кнопок можуть трохи відрізнятися. Якщо щось не знаходиться — шукайте за змістом (API Keys, SQL Editor, URL Configuration).

---

## 1. Створіть проєкт

1. Перейдіть на **https://supabase.com** і увійдіть (можна через GitHub або email).
2. Натисніть **New project**.
3. Оберіть організацію, введіть назву (наприклад, `physics-teacher-hub`).
4. **Database Password** — згенеруйте й збережіть у надійному місці. У застосунку цей пароль **не потрібен** і нікуди не вставляється.
5. **Region** — оберіть найближчий (наприклад, Central EU / Frankfurt).
6. Натисніть **Create new project** і зачекайте 1–2 хвилини.

## 2. Знайдіть Project URL і публічний ключ

1. У проєкті натисніть кнопку **Connect** угорі або відкрийте **Project Settings → API Keys** (і **Project Settings → Data API** для URL).
2. Скопіюйте:
   - **Project URL** — виглядає як `https://abcdefghijklm.supabase.co`;
   - **Publishable key** — починається з `sb_publishable_…`.
     Якщо в проєкті є лише вкладка **Legacy API keys**, візьміть ключ **anon** / **public** (довгий рядок, що починається з `eyJ…`).
3. Вставте їх у файл `.env.local` (див. [LOCAL_SETUP_UA.md](LOCAL_SETUP_UA.md), крок 5):

   ```env
   VITE_SUPABASE_URL=https://abcdefghijklm.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxx
   ```

> ⚠️ **Ніколи** не використовуйте **service_role** / **secret** (`sb_secret_…`) ключ у застосунку чи на GitHub. Він обходить усі правила безпеки. Публічний ключ безпечно мати у фронтенді, бо доступ до даних обмежують політики RLS з міграцій.

## 3. Виконайте SQL (один файл, один раз)

Підходить і для **нового** проєкту, і для проєкту, **де вже працюють інші ваші застосунки**: усі таблиці та функції Physics Teacher Hub мають префікс `pth_`, тригерів на реєстрацію немає, наявні таблиці, функції й акаунти не змінюються.

1. Ліве меню → **SQL Editor** → **New query**.
2. Відкрийте на комп'ютері файл `supabase/physics-teacher-hub-SQL.sql` (Блокнотом або VS Code), виділіть усе (**Ctrl + A**), скопіюйте й вставте в редактор Supabase.
3. Натисніть **Run** (або **Ctrl + Enter**). Має з'явитися `Success. No rows returned`. Якщо Supabase попросить підтвердити запуск — підтвердьте.

Перевірка: у **Table Editor** з'являться таблиці `pth_profiles`, `pth_classes`, `pth_sections`, `pth_topics`, `pth_topic_content`, `pth_materials`, `pth_formulas`, `pth_notes`, `pth_quizzes`, `pth_quiz_questions`, `pth_quiz_answer_keys`, `pth_allowed_emails` — усі з увімкненим RLS.

> Повторний запуск видасть помилку «already exists» — це означає, що все вже встановлено. Помилка зупиняє весь запуск, тож нічого не дублюється й не ламається.
>
> Папка `supabase/migrations/` містить той самий SQL, розділений на два файли (схема та функції) — для тих, хто звик до міграцій. Використовуйте **або** один файл, **або** два — не обидва варіанти.

Що створюється:
- таблиці з обмеженнями, індексами та часовими мітками;
- RLS і політики SELECT / INSERT / UPDATE / DELETE «лише власні записи»;
- заборона анонімного доступу;
- функції (усі з префіксом `pth_`): ідемпотентне початкове наповнення (9 клас, Розділ 1, 15 тем), сортування, безпечне видалення, дублювання теми та квізу, перевірка відповідей квізу, атомарне збереження питання, атомарний імпорт резервної копії, перевірка доступу.

Початкові 15 тем **не записані у фронтенді** — їх створює SQL-функція `pth_initialize_workspace()` під час першого входу кожного акаунта рівно один раз.

### Спільний проєкт: обмежте доступ лише собою (рекомендовано)

У спільному проєкті акаунти спільні для всіх застосунків: учень, зареєстрований в іншому вашому застосунку, зміг би увійти й сюди (ваших даних він не побачить, але отримав би власний порожній кабінет). Щоб пускати лише себе, виконайте в SQL Editor:

```sql
insert into public.pth_allowed_emails (email) values ('ваш@email.com');
```

Email пишіть **малими літерами**, точно як у вашому акаунті. Можна додати кілька email (кілька рядків `insert`). Інші акаунти побачать екран «Немає доступу» і нічого не зможуть ні прочитати, ні створити. Поки таблиця порожня — доступ відкритий для всіх акаунтів проєкту.

Переглянути список: `select * from public.pth_allowed_emails;`
Прибрати email: `delete from public.pth_allowed_emails where email = 'ваш@email.com';`

Список змінюється лише в SQL Editor — з браузера його не можна ні прочитати, ні змінити.

### Повне видалення

Файл `supabase/uninstall.sql` видаляє всі таблиці й функції `pth_` разом з даними Physics Teacher Hub, не зачіпаючи інші застосунки. Перед цим зробіть резервну копію (Налаштування → Експортувати дані).

## 4. Налаштуйте вхід email + пароль

**Authentication → Sign In / Providers → Email** (у старших версіях: Authentication → Providers → Email):

- **Enable Email provider** — увімкнено (зазвичай так за замовчуванням).
- **Confirm email** — оберіть:
  - **Увімкнено** (рекомендовано): після реєстрації надходить лист, і увійти можна лише після переходу за посиланням.
  - **Вимкнено**: вхід одразу після реєстрації. Зручно, якщо акаунт буде лише один — ваш.
- Мінімальна довжина пароля в застосунку — 8 символів.

> Вбудована поштова служба Supabase має суворий ліміт (кілька листів на годину) і призначена для тестів. Якщо листи не приходять — зачекайте, перевірте «Спам» або тимчасово вимкніть **Confirm email**. Для постійної роботи можна підключити власний SMTP (Authentication → Emails → SMTP Settings).

**Як створити акаунт:** у застосунку натисніть **Створити акаунт**. Альтернатива — **Authentication → Users → Add user → Create new user** (позначте **Auto Confirm User**), потім увійдіть у застосунку з цим email і паролем.

**Обмежити реєстрацію лише собою** (необов'язково): в **окремому** проєкті можна після створення свого акаунта вимкнути **Allow new users to sign up** (Authentication → Sign In / Providers). У **спільному** проєкті цього не робіть — перемикач діє на всі застосунки; натомість використайте `pth_allowed_emails` (див. крок 3).

> У спільному проєкті налаштування входу (підтвердження email, шаблони листів, ліміт листів) — спільні для всіх застосунків. Якщо ви вже маєте акаунт в іншому вашому застосунку цього проєкту — просто **увійдіть** тим самим email і паролем, реєструватися вдруге не потрібно.

## 5. Адреси перенаправлення (для листів підтвердження та скидання пароля)

**Authentication → URL Configuration**:

- **Site URL**: `http://localhost:5173`
- **Redirect URLs** → **Add URL**, додайте:
  - `http://localhost:5173/**`
  - `http://localhost:4173/**` (для `npm run preview`)
  - якщо Vite запускається на іншому порту (5174 тощо) — додайте і його.

### Як працює скидання пароля

1. На сторінці входу: **Забули пароль?** → введіть email → **Надіслати посилання**.
2. У листі натисніть посилання. Supabase поверне вас на `http://localhost:5173/?code=…&pth_action=recovery`.
3. Застосунок **до запуску маршрутизатора** обмінює код на тимчасову сесію, прибирає службові параметри з адреси й відкриває сторінку **Новий пароль** (`#/reset-password`).
4. Введіть новий пароль двічі → **Зберегти пароль**.

> Відкривайте посилання з листа **в тому ж браузері**, у якому натискали «Надіслати посилання». Це вимога захищеного PKCE-обміну: інший браузер чи пристрій покаже «Посилання недійсне» — просто надішліть новий лист.

Підтвердження email працює так само (код обмінюється автоматично, і ви потрапляєте на головну).

## 6. Сховище файлів (Storage)

**Не потрібне.** Застосунок зберігає посилання на файли (Google Drive, YouTube тощо), а не самі файли, тому бакети Storage не створюються і не налаштовуються.

## 7. Перевірка: вхід і збереження матеріалу

1. Запустіть `npm run dev` і відкрийте `http://localhost:5173/`.
2. **Створити акаунт** → підтвердьте email (якщо увімкнено) → увійдіть.
3. На головній має бути «Кількість тем: **15**» і «9 клас — Розділ 1. Електромагнітні явища».
4. Відкрийте тему 7 «Дослід Ерстеда…» → **Додати матеріал** → вставте посилання YouTube → тип «Відео» підставиться сам → введіть назву → **Зберегти**.
5. Натисніть **F5** — матеріал на місці.
6. У Supabase → **Table Editor → pth_materials** з'явився новий рядок.
7. Вийдіть і увійдіть знову (або відкрийте застосунок на іншому комп'ютері з тими ж ключами в `.env.local`) — дані ті самі, тем знову 15 (без дублікатів).

### Контрольний список після налаштування

- [ ] Реєстрація, вхід, вихід, вхід знову
- [ ] 15 тем після першого входу, без дублікатів після оновлення сторінки
- [ ] Збереження YouTube-матеріалу та відтворення відео на сторінці матеріалу
- [ ] Скидання пароля через лист
- [ ] Другий акаунт (інший email) не бачить даних першого
- [ ] Експорт резервної копії в **Налаштуваннях**

## Якщо застосунок колись буде опубліковано

Додайте адресу сайту (наприклад, `https://ваш-логін.github.io/physics-teacher-hub/`) у:
- **Site URL** (замініть localhost, якщо працюватимете переважно з опублікованої версії);
- **Redirect URLs** — у вигляді `https://ваш-логін.github.io/physics-teacher-hub/**`.

Інакше листи підтвердження та скидання пароля вестимуть на localhost.
