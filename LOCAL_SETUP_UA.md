# Запуск Physics Teacher Hub на комп'ютері з Windows

Ця інструкція для початківців. Займе близько 15 хвилин (без налаштування Supabase).

> Спочатку бажано виконати [SUPABASE_SETUP_UA.md](SUPABASE_SETUP_UA.md) — вам знадобляться **Project URL** і **публічний ключ**. Але встановити й запустити застосунок можна й раніше: без ключів він покаже екран із підказками.

---

## 1. Встановіть Node.js (LTS)

1. Відкрийте сайт **https://nodejs.org**.
2. Завантажте версію з позначкою **LTS** (рекомендована; підійде 22.x або новіша LTS).
3. Запустіть інсталятор і натискайте **Next** до кінця (налаштування за замовчуванням підходять).
4. Перевірте встановлення: натисніть **Win**, введіть `PowerShell`, відкрийте його та виконайте:

   ```powershell
   node -v
   npm -v
   ```

   Мають з'явитися номери версій (наприклад, `v22.12.0` і `10.9.0`). Якщо PowerShell пише «не розпізнано» — закрийте та відкрийте його знову або перезавантажте комп'ютер.

## 2. Відкрийте папку проєкту в терміналі

1. Розпакуйте архів проєкту, наприклад у `C:\Projects\physics-teacher-hub`.
2. Відкрийте цю папку в Провіднику (там мають бути файли `package.json`, `index.html` і папка `src`).
3. Клацніть в адресному рядку Провідника, введіть `powershell` і натисніть **Enter** — відкриється термінал уже в потрібній папці.

   Альтернатива: у PowerShell виконайте `cd C:\Projects\physics-teacher-hub`.

## 3. Встановіть залежності

```powershell
npm install
```

Це завантажить потрібні бібліотеки в папку `node_modules` (1–3 хвилини). Попередження (`npm warn …`) — нормальні; важливо, щоб не було слова `ERR!` наприкінці.

> Якщо PowerShell пише, що «виконання сценаріїв вимкнено», виконайте один раз:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` і підтвердіть `Y`. Або користуйтеся «Командним рядком» (cmd) замість PowerShell.

## 4. Створіть файл .env.local

У папці проєкту є файл `.env.example`. Скопіюйте його під назвою `.env.local`:

```powershell
copy .env.example .env.local
```

> Файли, назва яких починається з крапки, Провідник інколи приховує. Увімкніть **Вигляд → Показати → Приховані елементи** (Windows 11) або **Вигляд → Приховані елементи** (Windows 10). Також увімкніть показ **розширень імен файлів**, щоб не створити випадково `.env.local.txt`.

## 5. Впишіть URL і публічний ключ Supabase

Відкрийте `.env.local` у Блокноті (або VS Code) і замініть значення:

```env
VITE_SUPABASE_URL=https://ваш-проєкт.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxx
```

- Де взяти ці значення — у [SUPABASE_SETUP_UA.md](SUPABASE_SETUP_UA.md), крок 2.
- Підходить **publishable** ключ (`sb_publishable_…`) або legacy **anon** ключ (довгий рядок, що починається з `eyJ…`).
- **Ніколи** не вставляйте `service_role` / `sb_secret_…` ключ — застосунок відмовиться працювати з ним.
- Без лапок і пробілів навколо `=`. Збережіть файл.

Файл `.env.local` містить ваші ключі, тому він **не** завантажується на GitHub (це вже налаштовано у `.gitignore`).

## 6. Виконайте SQL-міграції

Якщо ще не зробили — див. [SUPABASE_SETUP_UA.md](SUPABASE_SETUP_UA.md), крок 3. Без міграцій застосунок покаже помилку «У базі даних немає потрібних таблиць».

## 7. Налаштуйте вхід (Authentication)

Див. [SUPABASE_SETUP_UA.md](SUPABASE_SETUP_UA.md), кроки 4–5: адреси перенаправлення `http://localhost:5173` і режим підтвердження email.

## 8. Запустіть сервер розробки

```powershell
npm run dev
```

Побачите приблизно таке:

```
  VITE v6.x.x  ready in 300 ms

  ➜  Local:   http://localhost:5173/
```

## 9. Відкрийте точну адресу, яку показав Vite

Скопіюйте адресу з рядка **Local** (зазвичай `http://localhost:5173/`) у браузер (Chrome, Edge, Firefox). Утримуючи **Ctrl**, можна клацнути на неї прямо в терміналі.

> Якщо порт 5173 зайнятий, Vite обере інший (наприклад, 5174) — тоді відкрийте саме ту адресу й **додайте її** в Redirect URLs у Supabase.

**Не відкривайте `index.html` подвійним клацанням** — так застосунок не запуститься. Працює лише через `npm run dev` (або `npm run preview` після збірки).

Далі: **Створити акаунт** → підтвердити email (якщо увімкнено) → увійти. Під час першого входу створиться «9 клас → Розділ 1» з 15 темами.

## 10. Зупиніть сервер

Поверніться у вікно терміналу й натисніть **Ctrl + C** (якщо запитає «Terminate batch job (Y/N)?» — введіть `Y`). Або просто закрийте вікно терміналу. Дані при цьому **не втрачаються** — вони в Supabase.

Наступного разу: відкрийте термінал у папці проєкту й знову виконайте `npm run dev` (`npm install` повторювати не треба).

## Збірка та перегляд готової версії

```powershell
npm run build
```

Перевіряє код (TypeScript) і створює оптимізовану версію сайту в папці `dist/`. Ця папка — те, що колись можна буде опублікувати (наприклад, на GitHub Pages). Її не потрібно завантажувати в репозиторій з кодом.

```powershell
npm run preview
```

Запускає зібрану версію з `dist/` на `http://localhost:4173/` — щоб перевірити, як працюватиме опублікований сайт. Якщо користуєтеся preview, додайте `http://localhost:4173/**` у Redirect URLs Supabase.

## Якщо щось пішло не так

| Проблема | Що зробити |
|---|---|
| Екран «Потрібно підключити Supabase» | Перевірте назву файлу `.env.local` (не `.env.local.txt`) та значення. Після зміни `.env.local` зупиніть сервер (Ctrl + C) і знову запустіть `npm run dev`. |
| «У базі даних немає потрібних таблиць» | Виконайте обидві SQL-міграції по черзі. |
| «Немає з'єднання з сервером» | Перевірте інтернет і `VITE_SUPABASE_URL` (має бути `https://…supabase.co`, без `/` наприкінці). Перевірте, що проєкт Supabase не призупинено (безкоштовні проєкти «засинають» після тижня без активності — їх можна відновити в панелі Supabase). |
| «Email ще не підтверджено» | Відкрийте лист від Supabase (перевірте «Спам») або вимкніть підтвердження — див. SUPABASE_SETUP_UA.md, крок 4. |
| `npm` не знайдено | Перевстановіть Node.js і відкрийте новий термінал. |
| Порожня сторінка | Відкривайте адресу з терміналу, а не файл `index.html`. Натисніть F12 → Console, щоб побачити помилку. |
