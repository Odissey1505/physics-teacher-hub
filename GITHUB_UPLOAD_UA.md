# Завантаження коду на GitHub через сайт (без командного рядка)

Ця інструкція пояснює, як зберегти **вихідний код** проєкту в репозиторії GitHub, використовуючи лише браузер.

> **Важливо.** Репозиторій GitHub — це сховище коду. Після завантаження сайт **не запускається і не з'являється в інтернеті автоматично**. Застосунок і далі запускаєте локально (`npm run dev`), а публікація сайту — окремий, необов'язковий крок у майбутньому (див. README.md, «Майбутня публікація»).

---

## Що завантажувати, а що — ні

| ✅ Завантажувати | ❌ НЕ завантажувати |
|---|---|
| папку `src/` | папку `node_modules/` (дуже велика, створюється командою `npm install`) |
| папку `supabase/` (SQL-міграції) | файл `.env.local` (там ваші ключі!) |
| папку `public/` | будь-які інші файли `.env` з реальними значеннями |
| `package.json`, `package-lock.json` | папку `dist/` (результат збірки) |
| `index.html`, `vite.config.ts`, `tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json`, `components.json` | паролі, service_role / secret ключі |
| `.gitignore`, `.env.example` (лише шаблон без ключів) | |
| папку `.github/` (файл `workflows/deploy.yml` — автоматична публікація) | |
| `README.md`, `LOCAL_SETUP_UA.md`, `SUPABASE_SETUP_UA.md`, `GITHUB_UPLOAD_UA.md` | |

Перед завантаженням відкрийте `.env.example` і переконайтеся, що там **шаблонні** значення (`YOUR-PROJECT-REF`, `YOUR-PUBLISHABLE-OR-ANON-KEY`), а не ваші справжні.

## 1. Створіть репозиторій

1. Увійдіть на **https://github.com** (або зареєструйтеся).
2. Угорі праворуч натисніть **+** → **New repository**.
3. **Repository name**: наприклад, `physics-teacher-hub`.
4. **Description** (необов'язково): «Цифровий кабінет учителя фізики».

## 2. Оберіть видимість

- **Private** — бачите лише ви (та ті, кого запросите). Рекомендовано для особистого кабінету.
- **Public** — код бачать усі. Це безпечно, якщо ви не завантажили `.env.local` і секретні ключі: публічний ключ Supabase захищений правилами RLS. Але приватний варіант спокійніший.

Не ставте позначки **Add a README file**, **Add .gitignore** та **Choose a license** — ці файли вже є в проєкті. Натисніть **Create repository**.

## 3. Відкрийте «Add file → Upload files»

На сторінці порожнього репозиторію натисніть посилання **uploading an existing file** (або кнопку **Add file → Upload files**).

## 4. Завантажте вміст проєкту зі збереженням структури папок

1. Відкрийте папку проєкту в Провіднику Windows.
2. Якщо там є `node_modules` або `dist` — **не виділяйте** їх (найпростіше: тимчасово перемістіть ці папки деінде або просто не включайте у виділення).
3. Виділіть **вміст** папки проєкту (не саму папку): `src`, `supabase`, `public`, `package.json`, `package-lock.json`, `index.html`, `vite.config.ts`, `tsconfig*.json`, `components.json`, `README.md`, `*_UA.md`, `.gitignore`, `.env.example`.
4. **Перетягніть** виділене у вікно браузера на сторінці завантаження. GitHub збереже структуру папок (наприклад, `src/pages/TopicPage.tsx`).
   - Кнопка **choose your files** відкриває вибір окремих файлів і **не** завантажує папки — тому краще перетягувати.
   - Перетягування папок працює в Chrome, Edge та Firefox.
5. Дочекайтеся, поки всі файли з'являться у списку під полем.

### Файли з крапкою на початку (.gitignore, .env.example)

Провідник Windows і деякі браузери можуть **приховати або пропустити** такі файли:
- увімкніть у Провіднику **Вигляд → Показати → Приховані елементи**, щоб їх побачити й виділити;
- після завантаження **перевірте** в репозиторії, чи є `.gitignore` та `.env.example`.

**Якщо якогось файлу немає — створіть його на сайті:**
1. У репозиторії: **Add file → Create new file**.
2. У полі назви введіть `.gitignore` (або `.env.example`).
3. Відкрийте файл на комп'ютері Блокнотом, скопіюйте весь текст і вставте в редактор GitHub.
4. Натисніть **Commit changes…** → **Commit changes**.

> Створювати так `.env.local` **не можна** — у ньому ваші ключі, і він не повинен потрапляти в репозиторій.

## 5–6. Перевірте, що все на місці

Перед підтвердженням погляньте на список файлів:
- є `src/`, `supabase/` (з `physics-teacher-hub-SQL.sql`, `uninstall.sql` і папкою `migrations/`), `public/`, `package.json`, `package-lock.json`, документація;
- **немає** `node_modules/`, `dist/`, `.env.local`.

Якщо випадково додали зайвий файл — натисніть ✕ біля нього в списку до коміту.

## 7. Зафіксуйте завантаження (Commit)

1. Унизу сторінки, у полі **Commit changes**, напишіть коротко: `Перша версія Physics Teacher Hub`.
2. Залиште **Commit directly to the main branch**.
3. Натисніть **Commit changes**.

Готово — код збережено. Відкрийте вкладку **Code** і переконайтеся, що структура папок правильна, а `README.md` відображається на головній сторінці репозиторію.

### Чого не робити

- Не завантажуйте **лише ZIP-архів** проєкту як єдиний вміст репозиторію — такий репозиторій незручно переглядати й неможливо нормально оновлювати. Завантажуйте розпаковані файли й папки.
- Не очікуйте, що GitHub «запустить» застосунок після завантаження — він тільки зберігає код.

## Якщо ключ випадково потрапив на GitHub

1. Видаліть файл у репозиторії (відкрийте файл → **⋯ → Delete file** → Commit).
2. Пам'ятайте, що файл залишається в історії комітів. Якщо це був **service_role / secret** ключ або пароль бази — **негайно** перевипустіть його в Supabase (Project Settings → API Keys / Database).
3. Публічний (publishable / anon) ключ не є секретом, але за бажання його теж можна перевипустити.

## Оновлення коду пізніше

Щоб замінити змінені файли: **Add file → Upload files** → перетягніть оновлені файли/папки (з тією самою структурою) → **Commit changes**. Файли з однаковими шляхами буде оновлено.

## Необов'язково: через Git у командному рядку

Якщо встановлено Git (https://git-scm.com), з папки проєкту:

```powershell
git init
git add .
git commit -m "Перша версія Physics Teacher Hub"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГІН/physics-teacher-hub.git
git push -u origin main
```

Файл `.gitignore` автоматично не пропустить `node_modules`, `dist` і `.env.local`.

## Публікація сайту (GitHub Pages)

1. **Settings → Pages → Build and deployment → Source: GitHub Actions** (не «Deploy from a branch»!).
2. Переконайтеся, що в репозиторії є файл `.github/workflows/deploy.yml`. Папки з крапкою браузер часто пропускає — тоді створіть файл вручну: **Add file → Create new file**, у полі назви введіть `.github/workflows/deploy.yml` (скісні риски автоматично створять папки), вставте вміст файлу з архіву → **Commit changes**.
3. Відкрийте вкладку **Actions**: збірка триває 1–2 хвилини. Зелена галочка — сайт опубліковано за адресою `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/`.
4. У Supabase → Authentication → URL Configuration → Redirect URLs додайте `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/**`.

Далі кожне завантаження коду в `main` автоматично оновлює сайт.
