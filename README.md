# Physics Teacher Hub

**Уся фізика. Усі матеріали. Один простір.**

Особистий цифровий кабінет учителя фізики (9 клас): теми й уроки, презентації, відео, документи, зовнішні квізи та ігри, симуляції й досліди, довідник формул з калькуляторами, теорія, приватні нотатки, вбудовані квізи з автоперевіркою, обране та «Скарбничка матеріалів».

Увесь вміст зберігається у **вашому проєкті Supabase** і доступний з будь-якого пристрою після входу в той самий акаунт. Інтерфейс — українською.

---

## Швидкий старт

| Що потрібно зробити | Інструкція |
|---|---|
| 1. Створити базу даних і вхід | [SUPABASE_SETUP_UA.md](SUPABASE_SETUP_UA.md) |
| 2. Запустити застосунок на своєму комп'ютері (Windows) | [LOCAL_SETUP_UA.md](LOCAL_SETUP_UA.md) |
| 3. Завантажити код на GitHub через сайт | [GITHUB_UPLOAD_UA.md](GITHUB_UPLOAD_UA.md) |

Коротко для тих, хто вже має Node.js:

```bash
npm install
copy .env.example .env.local   # у Windows; на macOS/Linux: cp .env.example .env.local
# впишіть у .env.local URL і публічний ключ Supabase
npm run dev
```

Відкрийте адресу, яку покаже Vite (зазвичай `http://localhost:5173/`). **Не відкривайте `index.html` подвійним клацанням** — Vite-застосунок так не працює.

### Три різні речі, які легко сплутати

1. **Запуск локально** — застосунок працює на вашому комп'ютері за адресою `http://localhost:5173`, поки відкрито термінал з `npm run dev`.
2. **Завантаження коду на GitHub** — це лише зберігання вихідного коду. Сайт від цього **не з'являється** в інтернеті.
3. **Публікація сайту** — окремий крок (наприклад, GitHub Pages у майбутньому). Зараз нічого не публікується автоматично. Див. розділ «Майбутня публікація» нижче.

## Можливості

- **Структура курсу** «Клас → Розділ → Тема → Матеріали». Під час першого входу автоматично (рівно один раз на акаунт) створюється «9 клас → Розділ 1. Електромагнітні явища» з 15 темами. Повторний вхід, оновлення сторінки чи видалення тем не створюють їх знову.
- **Теми**: створення, перейменування, опис, іконка або обкладинка, дублювання (разом з матеріалами, формулами, нотатками та квізами), сортування перетягуванням (мишею, пальцем або клавіатурою), переміщення між розділами, безпечне видалення з вибором «зберегти матеріали у Скарбничці».
- **Сторінка теми** з вкладками: Огляд · Теорія · Презентації · Відео · Формули · Експерименти · Квізи та ігри · Тести та контрольні · Нотатки вчителя.
- **Матеріали** 13 типів (додано «Експеримент / дослід» для письмових описів дослідів). Розпізнавання YouTube, Google Drive / Slides / Docs / Forms, Kahoot, Quizizz / Wayground, Wordwall, LearningApps, PhET; вбудований перегляд там, де провайдер це дозволяє, і завжди — «Відкрити в новій вкладці».
- **Бібліотека** з пошуком, фільтрами (тип, тема, джерело, тег, обране), сортуванням і виглядом «сітка / список».
- **Скарбничка матеріалів** — швидке збереження посилання без вибору теми, потім переміщення в тему.
- **Теорія та нотатки** — безпечний редактор (заголовки, списки, таблиці, посилання, зображення, виділення, формули `$…$`). Увесь HTML санітизується.
- **Довідник формул** — LaTeX (KaTeX), величини, одиниці, приклад, калькулятори на основі заздалегідь налаштованих шаблонів (сила Ампера, сила Лоренца, магнітний потік, ЕРС індукції, закон Ома, потужність, ККД) з перевіркою чисел і одиниць. Жодного `eval`.
- **Вбудовані квізи** — вибір варіанта (2–6), правда/неправда, коротка відповідь із чіткими правилами порівняння; проходження по одному питанню, підрахунок балів, пояснення, «Почати знову». Ключі відповідей зберігаються окремо й перевіряються на сервері.
- **Режим презентації** — повноекранний класний показ без меню, кнопок редагування, нотаток, приватних матеріалів і ключів відповідей (вони навіть не завантажуються в браузер). Клавіші: ← → / PageUp PageDown / пробіл, Home/End, F — на весь екран, Esc — вийти.
- **Глобальний пошук** (Ctrl + K) за темами, матеріалами, описами, тегами, формулами, квізами та нотатками.
- **Резервна копія**: експорт у версіонований JSON та атомарний імпорт (додати або замінити) з попереднім переглядом і пошуком дублікатів.
- Темна (за замовчуванням) і світла теми, адаптивний дизайн для телефона, планшета й комп'ютера, клавіатурна навігація.

## Технології

React 18 · TypeScript · Vite 6 · Tailwind CSS 4 · компоненти у стилі shadcn/ui (Radix UI) · Lucide · React Router (HashRouter) · Motion · TanStack Query · React Hook Form + Zod · Sonner · dnd-kit · KaTeX · TipTap + DOMPurify · Supabase (PostgreSQL, Auth, RLS).

Без Next.js, без серверного рендерингу, без власного Node-бекенда. Збірка — звичайні статичні файли.

## Структура проєкту

```
physics-teacher-hub/
├─ supabase/
│  ├─ physics-teacher-hub-SQL.sql    ← ПОВНЕ встановлення одним файлом (SQL Editor → Run)
│  ├─ uninstall.sql                  ← повне видалення об'єктів pth_
│  └─ migrations/                    ← той самий SQL двома файлами (схема, функції)
├─ src/
│  ├─ lib/          ← клієнт Supabase, API, типи, провайдери посилань, санітизація, калькулятори, резервні копії
│  ├─ context/      ← авторизація, тема, підтвердження, діалоги
│  ├─ components/   ← UI-компоненти, форми, картки, макет
│  └─ pages/        ← сторінки застосунку
├─ public/          ← іконка
├─ .env.example     ← шаблон налаштувань (скопіюйте в .env.local)
├─ LOCAL_SETUP_UA.md · SUPABASE_SETUP_UA.md · GITHUB_UPLOAD_UA.md
└─ package.json · package-lock.json · vite.config.ts · tsconfig*.json · index.html
```

## Змінні середовища

| Змінна | Призначення |
|---|---|
| `VITE_SUPABASE_URL` | URL проєкту Supabase, напр. `https://abcd1234.supabase.co` |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | **Публічний** ключ: `sb_publishable_…` або legacy `anon` |
| `VITE_BASE_PATH` | Необов'язково. Базовий шлях збірки (за замовчуванням `./`) |

Якщо URL або ключ не вказано, застосунок показує екран налаштування — він **не** підміняє базу даних локальним сховищем і не імітує вхід. Якщо випадково вказати секретний ключ (`service_role` / `sb_secret_…`), застосунок відмовиться працювати й попередить про це.

## Безпека

- Усі таблиці та функції мають префікс `pth_`, тож застосунок можна встановити в проєкт Supabase, де вже працюють інші застосунки. Тригерів на `auth.users` немає; наявні об'єкти не змінюються.
- Необов'язковий список дозволених email (`pth_allowed_emails`): якщо він не порожній, лише ці акаунти можуть читати й змінювати дані Physics Teacher Hub (перевірка — у RLS-політиках, на сервері).
- Row Level Security увімкнено на **кожній** таблиці з даними; доступ лише до власних записів (SELECT, INSERT, UPDATE, DELETE).
- Дочірні записи посилаються на батьківські **складеним ключем** `(id, owner_id)`, тому матеріал, нотатка чи питання фізично не можуть бути прив'язані до запису іншого користувача.
- Анонімна роль не має доступу до жодної таблиці.
- Ключі відповідей квізів — в окремій таблиці; режим проходження та презентації їх не завантажує, а перевірка виконується SQL-функцією.
- Rich text проходить DOMPurify; дозволені лише http/https/mailto-посилання та https-зображення.
- Одночасне редагування з двох пристроїв: збереження перевіряє версію запису (`updated_at`). Якщо запис уже змінено деінде — нічого не перезаписується мовчки, з'являється вибір «Зберегти мої зміни поверх» або «Переглянути новішу версію».
- У фронтенді — тільки URL проєкту й публічний ключ. Жодних секретів у коді.

## Стан перевірки

**Перевірено під час розробки:**

- `npm install`, `npm run dev` (екран налаштування без ключів), `npm run build` — успішно, без помилок TypeScript.
- SQL виконано у вбудованому PostgreSQL (PGlite) з імітацією ролей Supabase; пройдено 57 автоматичних перевірок, зокрема обмеження доступу за email, та ще 14 — встановлення поверх «чужих» таблиць `profiles`/`notes`/`classes`, функцій `set_updated_at`/`handle_new_user` і тригера `on_auth_user_created` (усе чуже лишилося незмінним; `uninstall.sql` прибирає лише `pth_`). Також: ідемпотентна ініціалізація, RLS та ізоляція двох акаунтів (читання, запис, зміна власника, прив'язка до чужої теми, виклик функцій від чужого імені), обмеження URL, безпечне видалення теми, дублювання теми й квізу, перевірка відповідей, конфлікт версій, атомарний імпорт.
- 64 наскрізні браузерні перевірки (headless Chromium) проти **локального емулятора** API Supabase на тій самій базі з RLS: реєстрація й вхід, 15 тем без дублікатів, CRUD і сортування тем, збереження YouTube-матеріалу та його перегляд після оновлення сторінки, редагування/дублювання/переміщення/видалення, Скарбничка, зовнішні квізи, обране, формули й калькулятор, теорія й приватні нотатки, вбудований квіз і бали, режим презентації без приватних даних у DOM, пошук «Ерстед», виявлення конфлікту редагування з «іншого пристрою», експорт/імпорт, мобільний і планшетний вигляд, ізоляція двох акаунтів, екран «Немає доступу» для акаунта поза списком email, повторний вхід.

**Не перевірено (немає доступу до реального проєкту Supabase):**

- Робота з **реальним** хмарним Supabase, синхронізація між різними фізичними пристроями, листи підтвердження email і скидання пароля (повний PKCE-обмін), реальні вбудовування YouTube/Google/PhET (у тестовому середовищі зовнішні сайти недоступні).

Після налаштування Supabase пройдіть контрольний список у кінці [SUPABASE_SETUP_UA.md](SUPABASE_SETUP_UA.md).

### Відомі обмеження

- Файли (PDF, зображення) зберігаються як **посилання**; пряме завантаження файлів у Supabase Storage не реалізовано.
- Метадані (назва, обкладинка) з чужих сайтів автоматично не завантажуються — це блокує браузер (CORS). Обкладинка підставляється лише для YouTube; назву вводите вручну.
- Kahoot, Quizizz / Wayground та більшість інших сайтів забороняють вбудовування — вони відкриваються в новій вкладці. Wordwall вбудовується лише за адресою з коду «Вставити» (`…/embed/…`).
- Усі записи користувача завантажуються в браузер одразу — для особистого кабінету (сотні–тисячі записів) це швидко.
- Режим презентації призначений для показу з екрана вчителя після входу; окремого публічного порталу для учнів немає.

## Публікація на GitHub Pages

Файл `.github/workflows/deploy.yml` автоматично збирає сайт (`npm ci` → `npm run build`) і публікує папку `dist/` після кожного коміту в гілку `main`.

1. Репозиторій → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Завантажте код (разом із `.github/workflows/deploy.yml` і `package-lock.json`). Хід збірки — на вкладці **Actions**.
3. Сайт буде за адресою `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/`.
4. Додайте цю адресу в Supabase → Authentication → URL Configuration → Redirect URLs: `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/**`.

Важливо: GitHub Pages не вміє виконувати сирий код React/TypeScript. Якщо Source стоїть на «Deploy from a branch», браузер покаже помилку `Expected a JavaScript-or-Wasm module script… MIME type "application/octet-stream"` — це означає, що опубліковано вихідний код замість зібраної версії.

URL і публічний ключ Supabase для збірки записано у workflow (вони публічні й однаково потрапляють у зібраний сайт). Щоб змінити їх без редагування файлу, створіть змінні `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY` у Settings → Secrets and variables → Actions → **Variables**.
